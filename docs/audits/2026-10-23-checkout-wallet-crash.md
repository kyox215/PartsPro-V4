# 2026-10-23 结账钱包勾选崩溃修复

## 原因与修复

录屏中客户选择自提、现金后，勾选钱包余额触发页面错误边界。正式源码在函数式状态更新中读取 `event.currentTarget.checked`；React 延后或重放该更新时，`currentTarget` 已变为 `null`。回归测试执行真实 JSX 回调并模拟事件结束，旧代码勾选/取消均报 `Cannot read properties of null (reading 'checked')`，修复后均通过。

改为在事件回调内立即取得布尔值，再交给状态更新函数。主工作区同类订单备注写法一并修正；正式版备注原本已经立即读取，不需改动。运行代码仅修改 `checkout-client.tsx` 的钱包回调。

## 业务闭环核对

- 余额预览按分计算：抵扣不超过余额或订单金额，剩余应付不小于零；覆盖等额、超额、部分、零余额及运费。
- 钱包或数量变化使报价和确认失效；失败阻止提交，可显式重试；旧请求不能覆盖新数量。
- REMAX 预售禁用钱包及现金，保留预售确认；本次没有改变此契约。
- 提交使用已确认报价和钱包选择；结果不明锁定编辑，重发复用原请求编号；成功回执显示实际抵扣及剩余应付，并只清理匹配购物车。
- 既有订单事务锁定钱包，最终抵扣取余额、请求和订单金额的最小值；全额抵扣标记已付。本次未修改 API、SQL、权限、环境变量或迁移。

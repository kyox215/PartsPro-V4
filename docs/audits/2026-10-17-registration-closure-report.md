## 遗留问题（未在本轮修改业务规则）

下列源码位置相对于候选 `.company-tmp/registration-i18n-20261017`，对应运行提交 `5d329f1`。

### P2-01：后台语言 Cookie 可能被继承为新客户的商城语言

- **触发条件**：浏览器没有 `partspro_locale_storefront`，但残留 `partspro_locale_admin=zh-CN`；新账户尚无 `preferred_locale`。
- **证据**：`src/i18n/request.ts:29` 注册前只读取商城 Cookie，缺省为 `it-IT`；`src/i18n/account-locale.ts:27` 的初始化读取却会回退后台 Cookie；验证码及 OAuth 成功后均调用语言初始化，随后账户语言优先于商城 Cookie。对真实函数传入模拟 Cookie，结果为注册前 `it-IT`、初始化 `zh-CN`，全程未写库。
- **影响**：客户可能从意大利语注册页跳到中文账户界面。尚无反馈客户的浏览器 Cookie 或账户偏好证据，不能断言就是该客户的根因。
- **建议**：商城新账户初始化使用商城当次实际语言或商城默认语言；只有明确的后台登录流程可读取后台偏好。保持既有账户主动选择的语言不被覆盖。
- **验收**：覆盖无 Cookie、商城 IT/ZH Cookie、仅后台 ZH Cookie、已有账户偏好、验证码/OAuth 两入口；验证完成后界面语言与注册时一致。

### P2-02：默认注册资料保存后，刷新会再次弹出补全窗口

- **证据**：`src/components/partspro/account-page.tsx:208` 初始化弹窗时 `forceSetup` 无条件生效；`:263` 保存成功在没有 `returnTo` 时仅 `router.refresh()`，没有清理 URL 的 `setup=1`。真实函数模拟确认默认路径执行 refresh，没有导航。
- **影响**：保存已经成功的客户再次刷新或重进同一个 URL，仍被当作首次设置，容易怀疑资料没有保存。
- **建议**：保存成功后清除 setup 标记；自动补全应以真实资料完整状态为依据。保留客户主动编辑资料的入口。
- **验收**：默认注册→保存成功→刷新不再自动弹窗；保存失败继续保留表单；`/checkout` 注册返回流程不受影响。

### P2-03：客户资料读取失败的 warning 没传给页面

- **证据**：`src/app/account/page.tsx:94` 的 `dataWarning` 合并了订单、售后、公司和钱包 warning，却遗漏 `customerProfile.warning`。API `GET /api/account/profile` 本身可以返回该 warning，账户页面的独立读链路没有使用它。
- **影响**：资料读失败可能表现为无资料或待创建，客户无法分辨“从未填写”与“暂时读取失败”，也缺少对应重试说明。
- **建议**：将资料 warning 纳入账户页错误状态；遇到读取失败时避免把缺失快照当作可直接覆盖的空资料。
- **验收**：模拟仅资料查询失败、其他数据成功，页面明确提示并提供重试，不误报保存成功或资料为空。

### P2-04：表单长度限制与 API 不一致，拒绝后缺少字段级指引

- **证据**：`src/app/api/account/profile/route.ts:13` 要求电话 5–40 字符、客户名 ≤160、税号 ≤32、完整地址 ≤240。`account-page.tsx:675` 的资料输入大多只有 required，未镜像这些限制。对实际 Zod schema 输入四位电话，确认返回 phone 校验错误；未调用线上 API。
- **影响**：浏览器认为可以提交，服务器却拒绝；本轮已把拒绝提示本地化，但仍未将返回 issues 定位到具体字段。
- **建议**：统一字段限制和组合地址长度校验，并将 API issues 映射到字段及其所属页签；后端校验继续保留。
- **验收**：短电话、超长名称/税号/地址、非法 PEC 均能明确定位；失败保留输入；合法资料照常保存。

### P3-01：返回个人中心具体栏目的目标被过度拦截

- **证据**：`src/lib/partspro-auth-redirect.ts:50` 可以保留 `/account?section=orders` 为 `returnTo`，但 `account-page.tsx:266` 保存时拒绝所有 `/account` 前缀，仅 refresh。真实函数模拟确认原订单栏目目标没有被使用。
- **影响**：客户完成资料后停留在账户默认页，需要重新寻找原订单或钱包栏目。
- **建议**：按规范化 URL 的 pathname 与 setup 参数防止循环，允许合法的账户栏目；保留对登录、认证和后台路径的边界。
- **验收**：账户订单/钱包栏目可返回，setup 自循环和外域重定向仍被阻止。

## 已确认有效的闭环与本次修复

- 实际正式版已能保留 `/checkout` 的 `returnTo`，资料保存成功后调用 `router.replace('/checkout')`。不能将“所有原始 next 都丢失”列为缺陷。
- 资料 PATCH 以当前认证用户的邮箱为准；前端不能通过修改 email 字段保存为其他用户。读取与更新使用既有用户会话，未新增 service role 客户端。
- 当前账户上下文把客户资料完整、active、assigned、同步无错误作为价格和下单门禁；本次未放宽。
- 资料错误现在按 API code/status 转换为翻译 key；未知错误不把原始后端消息展示给客户。错误保持打开时切换语言可同步更新。
- 原生 `input.validationMessage` 不再直接展示为网站错误提示；改用当前网站语言。这个与浏览器语言不同步的问题已在本轮修复。
- 促销截止日期已跟随账户当前语言；关闭按钮具有本地化可访问标签。客户名称、地址、商品名称及人工备注保留原文。

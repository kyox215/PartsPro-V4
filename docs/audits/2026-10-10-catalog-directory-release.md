## 优化建议与实际实现

| 问题 | 业务影响 | 本阶段实现与操作方式 |
| --- | --- | --- |
| 系列、品牌、分类只有固定前端名称，无法统一管理 | 管理员改名后前台仍旧名称；多语言和排序分散维护 | 商品管理新增“目录管理”。支持中文/意大利文显示名、排序，品牌/分类新增与启停；四个一级系列标识固定。电子产品显示为“电子产品·高端产品”。改显示名不重写商品业务值。 |
| 编辑目录和维护商品缺少连贯入口 | 反复返回搜索，容易选错系列或分类 | 目录中“查看商品”直接带对应筛选；“在此新建商品”预填系列/品牌/分类。商品创建先保存草稿，沿用现有审核与上架步骤。 |
| 无型号的通用电子产品可能不出现在品牌树 | 真实有售商品无法通过品牌导航找到 | 前台将目录中有公开商品的品牌与型号树合并；REMAX入口按品牌查询；分类、系列按配置显示和排序。 |
| 批量改归属容易只改一部分或覆盖新资料 | 前后台分类不一致，结果难核对 | 勾选本页商品 → 移动目录 → 选目标系列/分类并填原因 → 原子提交 → 重读。1–100件，每件带原始版本；任何冲突整批回滚。品牌变更仍走兼容性审核；涉及保护膜折扣规则的跨分类移动被阻止。 |
| 两名管理员的内容编辑互相覆盖 | 后保存者静默覆盖先保存者 | 商品PATCH携带原始微秒时间戳，数据库锁定并核版本；冲突拒绝保存，保留输入，要求重新核对。目录节点也有独立版本。 |
| 新建请求超时后重复点击可能生成重复草稿 | SKU和库存建档重复 | 创建/复制使用固定UUID与第一次请求内容；相同请求返回同一商品，变更内容拒绝重用。重放需要后台读取权限，成本字段按成本权限遮蔽。只有创建权限且丢失响应时须由有读取权限者核对。 |
| 只在单个页面清缓存，多实例仍可能展示旧目录 | 管理员保存成功但客户看不到修改 | 数据库修订号加入公开商品/导航缓存键；同页成功后通知刷新，客户重新进入、返回页面或重新获得焦点时读取配置并刷新。购物车/checkout跟随刷新事件重读，已有价格/库存规则继续由既有接口判断。 |
| 用一行全局计数器推进修订号 | 不同商品事务可能互相等待并死锁 | 修订事件追加；公开修订号在单一MVCC快照中读取base+事件数，不展示未提交更新。独立压缩只删除实际可见事件并原子补base，不阻塞普通商品写入。 |
| 手机长名称、分类与错误提示溢出；切页丢失目录草稿 | 编辑入口不可达或资料丢失 | 沿用现有Dialog/Sheet视口保护与滚动正文；目录手机列表和编辑区纵排、长文本换行。目录未保存切页签/目录/商品入口均确认，提交中不能离开；浏览器关闭也保护草稿。 |
